# Custodian — Especificación del agente del lado-usuario

> El Custodian es la infraestructura del lado-usuario: la extensión MV3 que le da a **Dian** acceso al browser — cookies, banners, storage, pestañas.
> Dian es el agente que opera sobre esa infraestructura. El Custodian es el cuerpo; Dian, la mente que lo dirige.
>
> Cust·ODÍA·n: trae *día* a un dominio que estuvo oscuro treinta años.

---

## 0 · Resumen

El Custodian es la **primera implementación de referencia del lado-usuario** en el ecosistema AIcookies. Mientras la `SPEC.md` define el contrato sitio↔agente, este documento define **qué hace el agente** del lado del browser.

| Atributo | Valor |
|---|---|
| Forma | Browser extension (Manifest V3) |
| Versión inicial | Custodian v0.2 |
| Plataformas v0.2 | Chrome, Edge, Brave (Chromium-based) |
| Plataformas futuras | Firefox (v0.3), Safari (v0.4) |
| Lenguaje | TypeScript |
| Storage | IndexedDB local · cero llamadas de red sin opt-in |
| Razonamiento | Dian (módulo separable · ver `DIAN.md`) |
| Licencia | MIT |

## 1 · Por qué un browser extension y no una PWA

**Decisión técnica:** Manifest V3 extension. No PWA. No app standalone.

Razones:

1. **Sólo una extension puede leer las cookies que el usuario ya tiene.** La API `chrome.cookies` está restringida a extensions con permiso explícito. Una PWA no tiene acceso a cookies de otros orígenes — vería sus propias cookies y nada más.
2. **Sólo una extension puede inyectar content scripts** en cookie banners de cualquier sitio. Sin esto, el "banner agent" no existe.
3. **Sólo una extension corre en background** sin que el usuario tenga una pestaña abierta. La curaduría periódica necesita ese runtime.
4. **Una PWA companion puede sumarse después** (v0.3+) como dashboard sincronizado opt-in. Pero el motor *tiene* que ser extension.

La PWA queda en el roadmap como visualización extendida, no como reemplazo.

## 2 · Las cinco capacidades operacionales (+ Dian, aparte)

El Custodian expone **cinco herramientas operacionales** que Dian usa para actuar sobre el browser. Dian es el agente que decide qué hacer; el Custodian es la infraestructura que lo hace posible.

```
   ┌─────────────────────────────────────────────┐
   │  Dian (agente · asesor ejecutivo)           │
   │  observe → razone → actúe → observe         │
   └────────────────┬────────────────────────────┘
                    │ usa
   ┌────────────────▼────────────────────────────┐
   │  Custodian (cuerpo · infraestructura MV3)   │
   │                                             │
   │  Reader · Classifier · BannerAgent          │
   │  Curator · ProtocolClient                   │
   └─────────────────────────────────────────────┘
```

Dian observa el estado del browser a través del Reader, razona, y actúa vía el resto de los módulos. Toda acción queda en el log inspeccionable. El usuario configura el nivel de autonomía.

Especificación completa de Dian en `DIAN.md`. Aquí, los cinco operacionales.

### 2.1 Reader — *"el cookie es transparente"* (P7)

Lee la realidad actual del browser sin intervenirla.

Inputs:
- `chrome.cookies.getAll({})` → todas las cookies HTTP del usuario, todos los dominios
- `chrome.storage.local` → preferencias del Custodian
- Content scripts → cookie banners visibles en pestañas abiertas
- (Futuro) IndexedDB / localStorage de cada sitio vía debugger API o user-initiated

Output: un **modelo unificado del estado de memoria persistente del usuario**:

```ts
type CookieRecord = {
  id: string;              // host_key + name + path
  host: string;
  name: string;
  value: string;           // truncated > 256 chars
  expires: number | null;  // unix ms
  setAt: number;           // observed first
  lastSeen: number;
  flags: { secure, httpOnly, sameSite };
  classification: Classification | null;
};
```

### 2.2 Classifier — *"el cookie razona"* (P2)

Le pasa las cookies a Dian. Devuelve clasificación + razonamiento.

```ts
type Classification = {
  category: 'essential' | 'functional' | 'tracker' | 'ad' | 'unknown';
  vendor: string | null;       // "Google Analytics", "Meta Pixel", etc.
  purpose: string;             // human-readable, generated by LLM
  confidence: number;          // 0..1
  reasoning: string;           // why this category
  classifiedAt: number;
  classifiedBy: 'llm' | 'rule' | 'user';
};
```

Estrategia v0.2:
- **Cache primero**: dataset estático de ~5.000 cookie names cubre el 80% sin invocar a Dian.
- **Dian para el long tail**: cookies desconocidas se baten en lotes vía `dian.classify()`.
- **Costo por usuario v0.2**: < $0.05/mes para un browser activo (la mayoría va por cache).

### 2.3 BannerAgent — *"el cookie negocia"* (P3)

Cuando el usuario llega a un sitio y aparece un cookie banner, el BannerAgent:

1. Detecta el banner vía heurísticas + Dian (CMP frameworks comunes: OneTrust, TrustArc, Cookiebot, Quantcast, custom).
2. Parsea las opciones disponibles.
3. Llama a `dian.decide(banner, directivasDelUsuario, historial)`.
4. Aplica la recomendación automáticamente o muestra una mini-UI según la confianza devuelta.
5. Logea la acción para `inspect()`.

El usuario nunca pierde el control: cualquier auto-decisión es revertible y muestra un toast suave ("auto-rechazado: 12 trackers, 3 funcionales aceptados").

### 2.4 Curator — *"cura su propia memoria"* (P5)

Corre periódicamente (default: 1× por semana, configurable).

Decisiones que toma:
- Borra cookies expiradas que el browser olvidó borrar.
- Borra cookies de sitios que el usuario no visitó en N meses (default 6).
- Borra trackers de sitios que el usuario explícitamente rechazó (cuándo el sitio los volvió a setear).
- Comprime el log interno cuando supera N entradas.
- Pide confirmación antes de cualquier acción agresiva. Default: dry-run + reporte semanal.

El Curator llama a `dian.curate(state, window)` para que Dian recomiende qué borrar. La decisión final la toma el usuario (o el Custodian si el usuario habilitó auto-curaduría). Esta es la única feature donde una decisión asistida por Dian **escribe** sobre la realidad del usuario. Por eso default es conservador.

### 2.5 ProtocolClient — *"habla la spec AIcookies"*

Cuando un sitio implementa `SPEC.md` v0.1+, el Custodian lo detecta y se comunica vía la API definida ahí (`ask`, `remember`, etc.).

Mecanismo de detección:
- El sitio expone un meta tag: `<meta name="aicookies-version" content="0.1">`
- O el sitio hace `window.dispatchEvent(new CustomEvent('aicookies:hello'))`
- El Custodian responde y queda como agente activo en esa pestaña.

A partir de ahí, el sitio **deja de leer cookies HTTP** y consulta al Custodian. La spec v0.1 ya define ese contrato — no requiere cambios.

## 3 · Arquitectura técnica (Manifest V3)

```
custodian/
├── manifest.json                  # MV3, permissions: cookies, storage, scripting, activeTab, <all_urls>
├── background/
│   ├── service-worker.ts          # event router, cron del Curator
│   ├── reader.ts                  # chrome.cookies wrapper
│   ├── classifier.ts              # cache + delega long-tail a Dian
│   ├── curator.ts                 # cron + recomendaciones vía Dian
│   └── dian/                      # módulo de razonamiento (ver DIAN.md)
│       ├── index.ts               # interfaz Dian + loader
│       ├── dian-claude.ts         # encarnación v0.2: Claude API
│       ├── dian-local.ts          # encarnación v0.3: WebGPU local
│       └── prompts/v1/            # templates versionados
├── content-scripts/
│   ├── banner-detector.ts         # detecta CMPs, ofrece selector observado
│   └── protocol-bridge.ts         # detecta sitios AIcookies-compliant
├── popup/
│   ├── index.html                 # dashboard del Custodian
│   ├── views/
│   │   ├── overview.tsx           # 3.412 cookies · 71% trackers · etc.
│   │   ├── classifier-results.tsx
│   │   ├── directives.tsx         # configurar reglas
│   │   └── inspect.tsx            # log completo (P7)
│   └── components/
└── lib/
    ├── classification-cache/      # dataset estático de vendors conocidos
    ├── doctrine.ts                # los 7 principios como invariantes de código
    └── shared-types.ts
```

## 4 · Permisos y privacidad

### 4.1 Permisos del manifest

| Permiso | Por qué |
|---|---|
| `cookies` | Leer y modificar cookies (Reader, Curator) |
| `storage` | IndexedDB para estado del Custodian |
| `scripting` | Inyectar content scripts en banners |
| `activeTab` | Operar en la pestaña activa del usuario |
| `<all_urls>` | Necesario para `cookies` cross-domain. **El Custodian no carga datos del DOM de los sitios** — sólo lo necesario para banners. |
| `alarms` | Cron del Curator |

### 4.2 Garantías de privacidad

- **Cero telemetría.** El Custodian no manda datos a ningún server propio. Nunca.
- **Cero cloud sync default.** Es opt-in explícito y separable. Si se activa, es E2E encrypted con clave derivada de passphrase del usuario.
- **Dian es opt-in.** El usuario provee su propia key de Claude (o descarga modelo local). Sin Dian, el Custodian funciona en modo `cache-only` (sólo clasifica cookies conocidas).
- **Open source.** Código auditable. Reproducible build.
- **No fingerprinting.** El ID interno del Custodian (`aic_...`) es local-only. Nunca se expone a sitios.

### 4.3 Lo que el Custodian NO HACE

- No bloquea sitios.
- No reescribe response headers.
- No intercepta HTTP a nivel network.
- No modifica el browser (Chrome flags, etc.).
- No habla con otros usuarios.
- No "aprende del agregado" — el aprendizaje es 100% local.

## 5 · Dian: el módulo de razonamiento

Dian es el único componente del Custodian que **piensa**. Vive como un módulo separable detrás de la interfaz `Dian`. El resto del Custodian no sabe ni le importa qué encarnación está corriendo.

| Encarnación | Cuándo | Privacidad |
|---|---|---|
| **Dian v0.2** · Claude API (key del usuario) | Hoy | Local-ish · sin telemetría |
| **Dian v0.3** · modelo local (WebGPU + `transformers.js`) | Cuando WebGPU madure | 100% local |
| **Dian v1.0** · `window.ai` nativo (Gemini Nano) | 2026–2027 | 100% local · sin descarga |

Si Dian no está disponible, el Custodian corre en **modo cache-only** — útil pero no inteligente.

Especificación completa: `DIAN.md`.

## 6 · UI · principios

- **Bone + dark.** Mismo lenguaje visual que el resto del proyecto.
- **Fraunces para titulares, DM Sans para body, DM Mono para datos técnicos.**
- **Densidad alta, ruido bajo.** El popup es información, no decoración.
- **El log es ciudadano de primera clase.** Se accede en un click. El usuario nunca pregunta "qué hizo el Custodian".
- **Toda acción del Custodian es revertible.** Y se ofrece desde el toast de confirmación.

## 8 · Relación con la spec

La `SPEC.md` v0.1 sigue siendo el contrato sitio↔agente. **No cambia.** El Custodian es el primer agente compliant del lado-usuario.

Visto desde el sitio: si el sitio implementa la spec, el Custodian es uno de los muchos agentes que pueden contestarle. Otros agentes podrán existir (otras extensions, browsers nativos con `window.ai`, AIs corporativos del lado-usuario, etc.).

Visto desde el usuario: el Custodian es **el único** agente que opera sobre todas las cookies del browser, con o sin spec implementada del lado-sitio.

## 9 · Certificación

El Custodian, al ser implementación de referencia escrita por el autor del estándar, **es AIcookies-compliant™ por construcción**. Sirve como baseline para certificar otras implementaciones.

Otros browser extensions que implementen las cinco capacidades de este documento pueden solicitar certificación según `CERTIFICATION.md`.
